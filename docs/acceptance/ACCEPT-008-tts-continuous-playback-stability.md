# ACCEPT-008: TTS 连续播放稳定性、章末防卡死与视口段落对齐验收手册

## 1. 快速开始与环境准备 (Get Started)

### 选项 A：本地前后端源码开发环境验证 (推荐开发联调)
```sh
# 终端 1：启动 Ktor 服务端
./gradlew :server:run

# 终端 2：启动 Web 前端开发服务器
npm --prefix web run dev
# 浏览器打开 http://localhost:5173 访问阅读器
```


## 2. 核心功能验收步骤 (Step-by-Step Verification)

### 用例 1：开启朗读时视口首个可见段落智能对齐（重点验证）
1. 打开任意一本书籍进入阅读器。
2. **滚动模式 (Scroll Mode) 验证**：
   - 将页面向下随意滚动若干屏幕，停在某个中间段落（此时顶部有固定导航栏 56px）；
   - 点击顶部工具栏的**听书图标（耳机）**开启朗读；
   - **预期表现**：朗读高亮光标**绝不会跳回章节开头**，而是精准定位在当前屏幕最上方第一个完整可见的段落，并立即开始朗读该段落首句。
3. **翻页模式 (Paginated Mode) 验证**：
   - 切换为翻页模式，往后翻若干页（如第 4 页）；
   - 点击开启朗读；
   - **预期表现**：朗读光标精准从当前展示分栏最顶部的首个完整段落开始朗读与高亮。
4. **章首标题验证**：
   - 处于章节最顶部时开启朗读，正常从 `<h1>` 标题分片开始朗读。

### 用例 2：长时间连续收听（突破 2 分钟死锁瓶颈，验证 5~10 分钟稳定播放）
1. 确认听书设置中引擎为 **Edge-TTS**（如“晓晓”或“云希”）。
2. 静止放置收听，保持自然播放超过 **3 分钟（观察超过 50 个分片/句子）**。
3. **预期表现**：
   - 音频持续平滑发音，句子逐句高亮向下滚动；
   - 彻底打破原先 2 分钟（40~50 句）必死锁卡死的规律；
   - 无需手动点击其他句子刷新，一路连续平稳朗读。

### 用例 3：章节末尾静音看门狗与跨章连播
1. 播放到章节末尾的最后 1~2 句话（或直接点击最后一句）。
2. 观察播放器在音频尾部 300~500ms 静音帧处的推进情况。
3. **预期表现**：
   - 停滞看门狗在 350ms 内自动判定并触发 `onEnd`；
   - 绝不会在章末最后一两句停滞静音卡死；
   - 顺利无缝切入下一章正文并继续连播。

### 用例 4：短句/对话风暴与手动跳选切播
1. 遇到连续极短对话（“好。”“快走！”）时，音频无断粮卡顿（5 分片前瞻缓冲）。
2. 在朗读过程中任意点击正文中的其他段落，瞬间销毁旧流并在新句子重锚定起播，且控制台与界面无报错弹窗。

## 4. 验收清单与核对确认 (Acceptance Checklist)
- [ ] 滚动/翻页模式下任意位置开启朗读，均精准从本屏最上方首个完整段落起播。
- [ ] 连续播放 3~5 分钟以上不出现无故静音卡死。
- [ ] 读到章节最后一句不会卡死，能顺利自动跳下一章连播。
- [ ] 短句密集处无卡顿，控制台无未捕获异常或错误弹窗。
