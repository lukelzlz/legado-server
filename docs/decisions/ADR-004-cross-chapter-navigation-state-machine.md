# ADR-004: 阅读器跨章反向翻页定位状态机与异步排版守卫

## 1. 决策背景 (Context)
在电子书阅读器（分栏翻页模式或垂直滚动模式）中，用户阅读流程不仅包括“向后翻页（下一页/下一章）”，还包括高频的“向前回翻（上一页/上一章）”。
传统实现中，切章通常直接加载新章节并重置到开头（`page = 0` 或 `scrollTop = 0`）。这导致用户从第 2 章第 1 页往回翻页时，被带到了第 1 章的开头，而非第 1 章的最后一页，破坏了连续逆向阅读的直觉。

同时，由于 Web 端正文采用 CSS 分栏、字体自适应与异步段落拆分，在 DOM 尚未完成重新测算与布局前立即执行定位跳转，会导致定位高度失真或回弹。

## 2. 裁定方案 (Decision)
1. **显式逆向翻页定位状态机（`targetPosition`）**：
   - 引入明确的定位目标状态：`targetPosition: 'top' | 'bottom' | null`。
   - 当用户从章节首触发“上一章”翻页或向上拖动时，显式将状态设置为 `targetPosition = 'bottom'`。
2. **异步排版完成度守卫 (Layout Readiness Guard)**：
   - 严禁在异步正文加载与分栏排版未就绪前盲目调用滚动。
   - 在 `ReaderScreen` 中挂载排版完成度回调与 `requestAnimationFrame` 守卫：
     - **分栏/双栏翻页模式**：等待总页数计算完成，跳转至最后一页（`pageIndex = totalPages - 1`）。
     - **垂直滚动模式**：等待正文容器高度稳定后，将 `scrollTop` 精确设置为 `scrollHeight - clientHeight`。
3. **上一章反向预加载（Reverse Preload Guard）**：
   - 在阅读到当前章节前 30% 时，启动上一章反向预加载，防止逆向翻页时出现空白等待。

## 3. 备选方案与否决理由 (Alternatives Considered & Why Rejected)

- **备选方案 A：仅在 `useEffect` 中简单监听章节变更并 `scrollTo(0, 999999)`**
  - *否决理由*：分栏模式下分栏宽度和页数是异步计算的，直接滚动无法更新翻页页码；滚动模式下图片或自定义字体加载会导致二次跳动。
- **备选方案 B：将所有章节正文拼成一个无限长单页 DOM**
  - *否决理由*：长篇小说章节累计会导致 DOM 极其庞大，且难以维护精准的当前章节阅读进度与离线缓存分片。

## 4. 后果与权衡 (Consequences & Trade-offs)

### 正面收益
- 完美契合实体书与原生阅读 App 的双向翻页心智模型。
- 单栏、双栏、宽屏和滚动模式下跨章切换均丝滑无跳动。

### 负面代价
- 组件内部需要维护状态机标志，但通过纯函数与状态守卫封装，逻辑清晰可测（98 项单测全部覆盖该场景）。
