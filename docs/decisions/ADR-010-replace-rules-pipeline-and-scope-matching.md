# ADR-010: 替换净化执行管道选型、作用域匹配与沙箱安全

## 1. 决策背景 (Context)

小说源站反爬混淆（如反义词对调、转码乱码、嵌入式广告）严重影响阅读体验。为了兼容 Legado 生态成熟的替换净化体系，需要裁定：
1. **替换净化规则的执行时机与执行层级**（服务端入库前 vs 客户端渲染前）；
2. **规则作用域 (Scope) 与排除范围 (ExcludeScope) 的匹配算法**；
3. **复杂 `@js:` 脚本替换在服务端的多协程并发与安全沙箱机制**；
4. **恶意/灾难性回溯（ReDoS）正则表达式的防卡死熔断机制**。

---

## 2. 裁定方案 (Decision)

### 2.1 执行管道位置：服务端入库前清洗（Server-side Ingestion Pipeline）
* 在 `RuleRunner.content()` 提取出原始 HTML/正文后，根据当前请求的 `bookName`、`author`、`sourceUrl` 从数据库加载所有启用的 `ReplaceRule`；
* 按照 `sort_order ASC` 依次执行链式清洗；
* 清洗后的最终干净正文统一写入 `book_content_cache`，并返回给客户端。
* **收益**：
  - 一次清洗，全域受益（Web 阅读器直出、离线整书缓存、TTS 连续音频流合成、TXT/EPUB 导出均无需重复计算）；
  - 降低前端低端移动设备的 CPU 与电池开销。

### 2.2 作用域匹配算法 (Scope Matching Algorithm)
* 规则的 `scope` 字段支持使用逗号 `,`、分号 `;`、加号 `+` 或换行隔开多个匹配项；
* 匹配模式：
  1. `scope.isNullOrBlank()`：默认匹配所有书籍与书源；
  2. 若 `scope` 包含特定值：只要当前书籍的 `bookName`、`author`、`bookSourceUrl` 或 `bookSourceName` 任一匹配（支持精确匹配与正则匹配），则视为命中；
  3. `excludeScope`：若配置，只要命中排除条件，立即跳过该规则。

### 2.3 替换规则求值引擎与安全沙箱
* **纯文本替换**（`is_regex == false`）：调用纯 JVM `text.replace(pattern, replacement)`，执行速度极快（纳秒级）；
* **普通正则替换**（`is_regex == true` 且 `!replacement.startsWith("@js:")`）：
  - 支持标准捕获组引用（`$1`, `$2` 等）；
  - 针对每条正则配置 `50ms` 超时守卫，防止 ReDoS 导致服务端 CPU 100% 悬挂；
* **JS 脚本替换**（`replacement.startsWith("@js:")` 或 `<js>` 包装）：
  - 在复用现有的 `JsSandbox`（Rhino Engine）中运行；
  - 注入 `result`（当前匹配项或全量正文）、`match`（捕获组）与上下文变量，实现高级动态字典互换（如成对反义词字典翻转）。

---

## 3. 备选方案与否决理由 (Alternatives Considered & Why Rejected)

### 备选方案 A：纯前端 Web 渲染管道执行
- **做法**：服务端只管抓取原始生肉并存库，前端拿到正文后在 React 渲染前由 JS 运行替换规则。
- **否决理由**：
  1. **TTS 语音朗读彻底失效**：服务端 Edge-TTS 连续音频流服务直接读取服务端正文，若服务端未清洗，TTS 听书依旧会念出“大丑阁上”与垃圾广告；
  2. **离线缓存污染**：整书离线缓存与导出的电子书仍然是脏数据；
  3. **大章节卡顿**：长章节由前端正则匹配会引起页面渲染丢帧与掉电。

### 备选方案 B：硬编码常见反义词映射到代码中
- **做法**：在 `RuleRunner` 中直接 hardcode 《宅魔女》或常见反爬词库。
- **否决理由**：违反开源生态扩展性与工程整洁度原则，无法应对未来上万种千奇百怪的源站混淆，必须采用用户可配置、可导入的通用规则引擎。

---

## 4. 后果与权衡 (Consequences & Trade-offs)

### 正面收益
- 完美兼容 Legado 官方与社区十万级 `replaceRules.json` 规则库生态；
- 彻底解决起点 VIP 反爬混淆、转码网站错别字、牛皮癣广告等痛点；
- 服务端、TTS、离线缓存全链路数据一致、纯净。

### 负面代价与防御措施
- **性能开销**：若用户导入数千条全局正则规则，逐条正则遍历可能增加章节加载耗时（约 5~20ms）。
  - **防御措施**：增加按 `scope` 建立内存倒排索引，优先仅加载当前书籍/书源匹配的规则；纯文本规则合并为单次 Aho-Corasick 或预编译正则过滤。
