# PROPOSAL-009: 书架分组管理与批量操作机制

## 1. 业务背景与问题痛点
随着用户加入书架的书籍增多（如几十本至上百本），当前书架仅支持按硬编码的“正在阅读 / 已读完 / 全部”三个粗粒度状态进行查看。
用户缺乏按小说题材（如“玄幻修仙”、“都市脑洞”）、阅读状态（如“追更中”、“待阅”、“养肥区”）或个人偏好进行灵活分类归档的能力；同时，当需要整理书架或批量调整书籍归属时，逐本打开管理弹窗操作极其繁琐低效。

## 2. 目标与非目标 (Goals & Non-Goals)

### Goals
1. **服务端单分组归属与元数据持久化**：
   - 支持自定义书籍分组（`book_group`），具备名称与排序权重（`sort_order`）。
   - 每本书籍（`book_shelf`）可归属于单个自定义分组，若未分配则归入默认的“未分组”池。
   - 保证数据一致性：删除分组时，原属于该分组的书籍自动安全降级归入“未分组”，严禁误删书籍或破坏阅读进度。
2. **RESTful 分组增删改查与批量操作接口**：
   - 提供分组的查询、创建、重命名、排序更新与删除接口。
   - 提供书籍所属分组变更接口，以及高性能原子批量操作接口（批量移入分组、批量标记阅读状态、批量移出书架）。
3. **沉浸式现代 Web 分组交互体验**：
   - **顶部分组标签栏（Group Tabs）**：横向支持流式展示全部、未分组及用户自定义分组，带书籍数量角标及“管理分组”入口。
   - **二级阅读状态过滤（Status Filter）**：在分组视图下无缝联动“全部 / 正在阅读 / 已读完”状态筛选。
   - **单书分组快捷调整**：在书籍详情与书籍管理弹窗（`BookManageModal`）中支持直接切换所属分组。
   - **分组管理弹窗（`GroupManageModal`）**：支持快速新建、重命名、排序与删除分组。
   - **批量管理模式（Batch Mode）**：支持在书架页面一键进入批量选择模式，支持多选、全选、反选，并浮动批量操作条进行一键批量移动与管理。

### Non-Goals
1. 本次不引入复杂的多对多多标签（Multi-Tag）系统，保持单分组模型的轻量、直观与高可靠性。
2. 本次不引入远程跨端多用户权限隔离系统，仍保持现有单/多用户 Session 架构下的书架统一管理。
3. 本次不修改底层阅读器解析与 TTS 播放逻辑。

## 3. 核心用户故事 (User Stories)

- **Story 1（创建与查看分组）**：
  作为读者，我在书架页点击“+ 管理分组”，输入“修仙追更”并创建。创建后顶部分组栏立即出现“修仙追更 (0)”标签。
- **Story 2（书籍分配分组）**：
  作为读者，我在书架卡片点击“管理”按钮，在弹窗的“所属分组”下拉菜单中选择“修仙追更”并保存。该书籍立即归入“修仙追更”分组，且卡片与角标数量实时更新。
- **Story 3（分组与阅读状态联动筛选）**：
  作为读者，我点击“修仙追更”分组 Tab，下方展示该分组下的所有书籍；我再点击“正在阅读”，列表精准过滤出该分组下尚未读完的书籍。
- **Story 4（批量整理书架）**：
  作为读者，我在书架点击“批量管理”，勾选了 5 本刚刚搜索加入的新书，点击底部“移动至分组”，选择“玄幻精品”，这 5 本书被一次性批量移入该分组并提示成功。
- **Story 5（安全删除分组兜底）**：
  作为读者，我删除了一个名为“历史待看”的分组（组内有 3 本书），系统弹出确认提示。确认删除后，该分组被移除，原组内的 3 本书自动保留并归入“未分组”，书籍的离线缓存与阅读进度完全不受影响。
- **Story 6（分组排序与重命名）**：
  作为读者，我在分组管理弹窗中将“常用追更”分组上移到第一位，并将“待阅”重命名为“养肥区”，保存后书架顶部 Tab 栏的排列顺序与名称即刻同步更新。

## 4. 验收基准 (Acceptance Criteria)

- [ ] **数据库与迁移**：
  - `book_group` 表自动建立并支持 `id`, `name`, `sort_order`, `created_at`。
  - `book_shelf` 表通过 PRAGMA 动态迁移无损新增 `group_name` 字段。
- [ ] **服务端接口与单测**：
  - 分组 CRUD 接口测试通过（创建重名防重、删除时外键级联/数据迁移、排序更新）。
  - 批量操作接口（`/api/bookshelf/batch`）测试通过。
  - 所有 `./gradlew :server:test` 全部绿色通过。
- [ ] **Web 前端交互与类型检查**：
  - `npm --prefix web run check` 与 `npx tsx web/test/run-all.ts` 零错误。
  - 分组 Tab 切换平滑无卡顿，数量统计准确。
  - 批量管理模式勾选流畅，移动分组后即时响应。
  - 分组管理弹窗操作友好，具备边界防呆提示。
