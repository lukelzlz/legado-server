# PROPOSAL-014: 书源批量整理、分组维护与轻量连通性健康体检体系

## 1. 业务背景与问题痛点

随着用户导入的书源数量不断增长（往往达到数百甚至上千个），现有书源管理体系面临以下痛点：
1. **缺乏批量操作能力**：目前书源只能在侧边栏或列表项中逐个点击查看和删除，无法多选、无法批量启用/停用、无法批量导出或批量调整分类分组，整理大量书源极其耗时费力。
2. **失效书源淤积严重拖慢搜索性能**：书源站点由于上游域名过期更换、服务器宕机关站、防盗链策略变更或反爬风控拦截等原因容易逐渐失效。大量死链书源残留在书库中，导致每次全站并发搜索时产生大量无效的 TCP 连接挂起与超时等待，严重拖慢整体搜索速度、消耗服务器带宽与系统资源。
3. **缺乏健康度可视化与快捷自清洁机制**：用户无法直观获知当前哪些书源依然可用、各自响应延迟如何，缺乏一键禁用或删除全部死链书源的自清洁手段。

---

## 2. 目标与非目标 (Goals & Non-Goals)

### Goals (目标)
1. **多选与批量状态管理体系**：
   - 在书源管理页提供一键进入/退出「批量管理」模式，支持复选框勾选、全选（Select All）、全不选（Clear All）、反向选择（Invert Selection）以及按当前搜索/分组筛选结果一键全选。
   - 提供批量操作动作条：批量启用（Enable）、批量停用（Disable）、批量删除（Delete with Confirmation）、批量导出为标准 Legado JSON 文件（带有标准时间戳命名）。
2. **灵活的批量分组归类与维护**：
   - 支持对选中的多个书源统一移动到指定分组。
   - 分组选择器支持从已有分组下拉选取、创建输入全新分组名称、或一键清空/移出分组。
3. **轻量快速并发连通性体检 (Health Probe)**：
   - 服务端提供轻量高效的书源连通性与语法健康检测端点，通过 8 并发协程池探测 `bookSourceUrl` 域名连通性、搜索入口可达性与规则语法有效性（单源 5 秒硬超时，杜绝协程阻塞）。
   - 前端提供实时体检进度指示条（百分比、已完成数/总数、实时用时）、响应往返耗时（ms）与细粒度健康状态打标：
     - 🟢 **健康流畅**（< 1500ms，HTTP 200，规则正常）
     - 🟡 **响应迟缓**（1500ms ~ 4500ms 或重定向）
     - 🔴 **连接失效**（> 5000ms 超时、DNS 解析失败、SSL 握手错误、HTTP 404/502/503）
     - 🔒 **拦截/需登录**（HTTP 403 / Cloudflare 拦截）
4. **失效书源一键自清洁与重试机制**：
   - 体检完成后提供快捷处置通道：
     - 「一键停用所有失效源」：将体检失败的书源原子设为禁用状态（`enabled = false`），立竿见影提升搜索吞吐，同时保留配置便于日后排查。
     - 「一键删除所有失效源」：弹出明确受影响数量的二次确认弹窗后，彻底物理删除所有死链书源。
     - 「仅重试失败项」：网络抖动后仅对标红的失败书源发起快速复检。
5. **现代化交互与移动端自适应**：
   - 原生融入现有「书源管理」页面，采用响应式底部悬浮操作栏（Floating Action Bar），全面适配桌面端、平板与移动端安全区（`env(safe-area-inset-bottom)`），所有辅助按钮严格声明 `type="button"`。

### Non-Goals (非目标)
1. **不做重型全链路正文深度抓取**：本次体检聚焦于基础连通性与语法有效性，不针对每个书源深度抓取整本目录和正文，杜绝高耗时与大面积触发上游反爬封 IP。
2. **不破坏原有单源编辑与 Web 登录流程**：原有的单个书源规则编辑、调试（Debug SSE）、JSON 导入与 WebView 登录鉴权逻辑保持 100% 兼容。
3. **不引入重型外部任务队列**：体检与批量操作依托 Ktor 原生协程与轻量并发通道，保持服务端零额外基础设施依赖。

## 3. 详细核心用户故事 (User Stories)

### Story 1: 批量多选与状态集中管控
- **前置条件**：用户已导入了 150 个网络书源，进入「书源管理」页面。
- **主流程**：
  1. 用户点击列表右上角的「批量管理」按钮，界面平滑过渡至批量管理模式：每个书源卡片/列表项左侧出现复选框，页面底部升起浮动操作栏（Floating Action Bar）。
  2. 浮动操作栏左侧实时显示当前选择计数（如 `已选择 0 / 150 个书源`），并提供快捷操作菜单：「全选」、「全不选」、「反选」。
  3. 用户在上方的搜索框输入关键词（如 `笔趣阁`），列表过滤出 12 个相关书源，用户点击「全选」，系统智能选中当前过滤出的这 12 个书源，操作栏计数更新为 `已选择 12 个书源`。
  4. 用户点击操作栏中的「批量停用」，系统发出批量更新请求，所有选中书源的状态被原子更新为禁用，界面上的书源启用状态徽标即刻变为灰色「已停用」，并弹出 Toast 提示 `已批量停用 12 个书源`。
  5. 用户点击操作栏中的「批量启用」，12 个书源立即恢复为启用状态。
  6. 用户点击「退出批量」，界面恢复为常规单选浏览与编辑视图，选中的临时状态安全重置。

### Story 2: 批量分组维护与分类重构
- **前置条件**：用户从多个订阅源导入了大量书源，分组混乱或大量书源未分配分组（`group` 为空）。
- **主流程**：
  1. 用户在批量管理模式下，勾选了 35 个常用的优质小说源。
  2. 用户点击底部操作栏的「修改分组」按钮，系统弹出「批量设置分组」模态弹窗。
  3. 弹窗内展示当前系统中已存在的所有分组标签列表（如 `精品`、`出版物`、`动漫小说`），用户可直接点击已有分组快速填充，也可以在输入框中输入新的自定义分组名称（如 `高质量备用`）。
  4. 弹窗同时提供「清空分组（移出所有分组）」快捷选项。
  5. 用户输入 `高质量备用` 并点击「确认修改」，服务端执行批量事务更新，这 35 个书源的 `source_group` 属性同步更新为 `高质量备用`。
  6. 弹窗关闭，页面顶部的分组筛选器自动出现新分组 `高质量备用 (35)`，用户点击该分组即可单独过滤查看这 35 个书源。

### Story 3: 批量安全删除与级联清理
- **前置条件**：用户想要清理 20 个不再使用的旧书源。
- **主流程**：
  1. 用户在批量模式下勾选这 20 个书源。
  2. 用户点击底部操作栏的「批量删除」危险按钮。
  3. 系统弹出明确的二次确认危险弹窗，弹窗内容列出：`即将永久删除以下 20 个书源（包括：笔趣看、快读网 等），删除后不可恢复。是否继续？`
  4. 用户点击「确认删除」，服务端开启事务：批量删除 `source` 表中的记录，并级联清理对应的 `source_login_state` 登录凭据与缓存，返回成功删除计数。
  5. 前端列表立即平滑剔除被删书源，右侧详情区若恰好选中被删书源则优雅置空，Toast 提示 `成功删除 20 个书源`。

### Story 4: 批量导出为标准备份 JSON
- **前置条件**：用户整理好了特定分组（如 `精选书源`）的 18 个书源，需要分享给好友或备份导出。
- **主流程**：
  1. 用户筛选出 `精选书源` 并全选这 18 个书源。
  2. 用户点击底部操作栏的「导出选中」按钮。
  3. 系统聚合这 18 个书源的原始标准 Legado JSON 配置对象，组装为标准 JSON 数组字符串。
  4. 浏览器立即触发文件下载，文件命名遵循标准规范（例如 `legado_sources_export_20260916_2100.json`）。
  5. 导出的 JSON 文件完全兼容 Legado 手机端 App 以及本系统的直接导入。

### Story 5: 轻量快速连通性体检与多维状态探测 (Health Probe)
- **前置条件**：用户书库内有 120 个书源，感觉近期搜索变慢，希望快速找出坏源。
- **主流程**：
  1. 用户在书源管理页点击顶部的「健康体检」按钮。
  2. 系统弹出「书源健康体检」面板，显示待检测书源总数（默认当前全部或启用中的书源），用户点击「开始快速体检」。
  3. 服务端启动 8 并发协程池对目标书源的 Host 与搜索入口进行轻量 HTTP 探测及语法解析，单源设置 5 秒硬超时；
  4. 前端体检面板实时滚动更新：
     - 顶部显示动态进度条（如 `78% 正在检测... (94/120)`）、已用时间（如 `4.2s`）、当前成功率（如 `91%`）。
     - 下方列表实时动态渲染每一个书源的检测结果：
       - 🟢 **笔趣阁**：`118ms` 连通正常 (HTTP 200)
       - 🟡 **小书亭**：`2340ms` 响应较慢
       - 🔴 **看书吧**：`5000ms` 连接超时 (Connect Timeout)
       - 🔴 **某个已关闭站点**：DNS 解析失败 (UnknownHostException)
       - 🔒 **某 VIP 站点**：HTTP 403 / 访问受限
  5. 体检过程中，用户可随时点击「停止体检」中断后台协程。
  6. 体检完成后，面板顶部呈现结构化体检总结：`体检完成：共检测 120 个书源，其中 108 个正常，4 个响应迟缓，8 个连接失效`。

### Story 6: 失效书源一键自清洁与针对性重试
- **前置条件**：Story 5 中的体检已完成，发现了 8 个连接失效（🔴）的书源。
- **主流程**：
  1. 体检面板底部高亮展示快捷处置工具区：
     - **「一键停用失效源 (8)」**
     - **「一键删除失效源 (8)」**
     - **「仅重试失效项 (8)」**
  2. 用户点击「一键停用失效源 (8)」，系统立即发起批量更新请求将这 8 个书源的 `enabled` 设为 `false`。
  3. 操作完成后，面板与主列表立即同步状态，并提示 `已成功停用 8 个失效书源，全站搜索已自动排除这些死链`。
  4. 若用户选择「仅重试失效项」，系统仅对这 8 个标红书源再次并发探测，防止偶发网络抖动造成误判。

### Story 7: 移动端全面屏安全区与手势自适应
- **前置条件**：用户在 iPhone / Android 手机浏览器或 PWA 独立窗口中打开书源管理页。
- **主流程**：
  1. 用户点击「批量管理」，底部浮动操作栏自适应浮现，严格预留 `env(safe-area-inset-bottom)` 安全区垫底空间，杜绝遮挡系统手势条（Home Indicator）或底部虚拟导航键。
  2. 列表滚动容器自动增加底部 padding 避免最后一项被浮动栏遮挡。
  3. 操作栏各功能按钮（全选、启停、改组、删除、退出）按移动端排版自动流式折叠或图标化呈现，触控区域均符合不小于 44x44px 的无障碍标准。

## 4. 接口与数据契约设计

### 1. 批量操作接口 `POST /api/sources/batch`
- **Request Body**:
```json
{
  "action": "enable" | "disable" | "delete" | "set_group",
  "ids": ["https://source1.com", "https://source2.com"],
  "group": "精品小说" // 仅当 action 为 set_group 时需要
}
```
- **Response**:
```json
{
  "ok": true,
  "affected": 2,
  "action": "set_group",
  "message": "已成功处理 2 个书源"
}
```

### 2. 批量健康体检接口 `POST /api/sources/health-check` (或流式 SSE)
- **Request Body**:
```json
{
  "ids": ["https://source1.com", "https://source2.com"], // 为空则默认体检所有/所有已启用书源
  "timeoutMs": 5000
}
```
- **Response**:
```json
{
  "total": 50,
  "successCount": 45,
  "slowCount": 3,
  "failedCount": 2,
  "durationMs": 4250,
  "results": [
    {
      "id": "https://source1.com",
      "name": "笔趣阁",
      "ok": true,
      "latencyMs": 142,
      "statusCode": 200,
      "statusCategory": "valid", // "valid" | "slow" | "failed" | "blocked"
      "error": null
    },
    {
      "id": "https://source2.com",
      "name": "失效小说网",
      "ok": false,
      "latencyMs": 5002,
      "statusCode": 0,
      "statusCategory": "failed",
      "error": "Connect timed out (5000ms)"
    }
  ]
}
```

## 5. 异常处理与边缘边界 (Edge Cases)

1. **批量操作全部为空（ids 为空数组）**：
   - 前端拦截提示 `请先勾选需要操作的书源`，后端直接返回 400 `empty_selection`。
2. **批量删除包含当前正在阅读或书架正在使用的书源**：
   - 删除书源仅清理 `source` 与 `source_login_state` 表，书架（`book_shelf`）中的既有离线缓存与书籍记录予以保留，避免读者书架崩溃，同时在换源时标注原源已移除。
3. **体检过程中网络彻底断开**：
   - 服务端单源 5s 超时正常兜底返回失败，前端捕获整体网络错误并展示友好重试提示。
4. **超长书源列表（> 1000 个）批量 SQL 性能**：
   - 采用 SQLite 参数化批处理（每批次最多 200 个或分批执行），避免超出 SQLite 变量上限（999/32766 参数上限）。
5. **重名分组与空字符串分组**：
   - 输入全空白字符自动转换为 `null`（即未分组），已有分组名自动 trim 去除首尾空格。

## 6. 验收基准 (Acceptance Criteria)

- [ ] **批量选择能力**：支持单选、多选、全选、全不选、反选，列表数量与浮动操作栏计数完全准确。
- [ ] **批量状态更新**：批量启用与批量停用后，数据库 `enabled` 字段即刻生效，UI 状态徽标实时刷新。
- [ ] **批量分组更新**：能将选中的多个书源批量移入现有分组、新建分组或清空分组。
- [ ] **批量删除与确认**：弹出包含数量与书源名称摘要的危险确认弹窗，确认后原子删除并级联清理。
- [ ] **批量导出**：导出标准格式 `.json` 文件，包含所有选中书源配置，可再次无损导入。
- [ ] **轻量健康体检**：服务端 8 并发协程池严格控制在 5s 超时内完成探测，前端进度条、延迟（ms）与分类徽标渲染流畅。
- [ ] **失效源自清洁**：体检后可一键批量停用所有失败书源。
- [ ] **全套自动化测试**：`./gradlew :server:test` 与 `npm --prefix web run check && npx tsx web/test/run-all.ts` 全部绿灯通过。
- [ ] **移动端与安全区适配**：在各尺寸屏幕下浮动栏与弹窗均能良好展现，无内容遮挡。
