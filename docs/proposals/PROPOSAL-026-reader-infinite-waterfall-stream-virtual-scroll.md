# PROPOSAL-026: 连续滚动模式升级为无限瀑布流与虚拟窗口阅读引擎

## 1. 业务背景与问题痛点

在当前的阅读器设计中，虽然翻页方式提供「连续滚动（scroll）」和「平移分页（paginate）」两种选项，但在连续滚动模式下，底层仍采用「单章渲染模型（Single Chapter Model）」。
当读者滚动阅读到本章最底部时，阅读流被迫中断，滚动条卡在页面末尾，无法像现代信息流应用（如 Twitter、微博动态流）那样自然地向下顺畅滚动下一章。

用户期望：
在连续滚动模式下，实现真正的**瀑布屏流式加载（Infinite Waterfall Stream）**与**虚拟滚动（Virtual Window）**，下一章直接在下方拼接呈现，读者可以不间断地向下无缝滑动阅读全书。

## 2. 目标与非目标 (Goals & Non-Goals)

### 目标 (Goals)
1. **多章无缝流式拼接（Infinite Chapter Stream）**：
   在连续滚动模式下，阅读区域容器由单章正文重构为章节流水线。滚动接近当前内容末尾（预载阈值）时，系统自动在正文末尾追加（Append）下一章，并在章节交接处渲染清晰美观的章节分隔标识与新章节标题。
2. **长篇阅读虚拟窗口保护（Virtual Window & Memory Safeguard）**：
   连续阅读几十甚至上百章时，防止几万个段落 DOM 节点堆积导致浏览器内存溢出与滚动掉帧。建立动态视口滑动窗口机制，距离视口过远的已读章节以高度占位容器（Spacer）卸载，保持 DOM 节点数恒定在合理规模。
3. **滚动视口章节动态感知（Active Chapter Observer）**：
   页面滚动时，实时监测当前视口中心所处于的章节，顶栏标题、底栏章节进度（如 `12 / 500`）、侧边栏目录高亮以及阅读进度持久化（`saveProgress`）自动动态跟随切换。
4. **目录精准直达与流重置（TOC Direct Jump & Stream Reset）**：
   当读者通过目录、搜索或进度滑块跳转到任意章节时，章节流以目标章节为首项进行平滑重置，并准确定位。
5. **平移分页模式保持独立**：
   平移分页模式（`pageMode === 'paginate'`）依然保持原有的左右轻扫翻页和单栏/双栏排版逻辑，互不干扰。

### 非目标 (Non-Goals)
- 本次不对服务端数据库 schema 和 API 契约进行破坏性变更，完全复用现有 `/api/books/chapters`、`/api/books/content` 与 `/api/progress` 端点。

## 3. 核心用户故事 (User Stories)

- **Story 1（顺畅滑入下一章）**：
  作为读者，在「连续滚动」模式下阅读《诡秘之主》第一章，当我把屏幕滑到第一章末尾时，第二章的标题和正文已经自然而然地展现在第一章末尾之后，我可以像刷信息流一样持续向下划动阅读，没有任何卡顿、跳页或按钮点击阻碍。
- **Story 2（滚动过程进度与章节同步感知）**：
  作为读者，当我持续向下滚动滑过第一章进入第二章中段时，顶栏的书名标题自动更新为「诡秘之主 - 第二章 局面」，底栏的章节进度自动从 `1 / 5` 变为 `2 / 5`，退出后重新进入时能精准恢复到第二章该阅读位置。
- **Story 3（极端连续阅读流畅无卡顿）**：
  作为重度读者，一口气连续滚读 30 章，阅读器依靠动态虚拟窗口卸载遥远的上游章节 DOM，页面保持 60 FPS 顺滑，没有内存飙升与浏览器掉帧。
- **Story 4（目录跨章任意跳转）**：
  作为读者，在流式阅读过程中打开目录抽屉，点击跳转到「第 100 章」，页面瞬间重置流并准确定位于第 100 章顶部，继续往下滚可连读第 101 章。

## 4. 验收基准 (Acceptance Criteria)

- [ ] 连续滚动模式下，滚动至底部前自动追加下一章，滚动条平滑延伸无跳变。
- [ ] 视口滚动动态感知章节变化，实时更新顶栏标题与底栏进度。
- [ ] 目录点击跳转能正确重置章节流并定位于目标章节。
- [ ] 平移分页模式不受任何影响，测试套件全部通过。
