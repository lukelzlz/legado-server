# PROPOSAL-035: 大规模书源搜索范围选择器（多分组与多书源）

## 1. 业务背景与问题痛点

当前书库搜索已经支持按单个书源分组搜索，也保留了单个书源下拉框。但当服务端配置约 10,000 个书源时，普通下拉框无法有效定位目标书源：

- 用户需要在大量选项中滚动查找，无法按名称、地址或分组快速搜索；
- 现有单个书源选择不支持一次选择多个书源；
- 现有单分组选项卡不支持同时选择多个分组和额外的单个书源；
- 前端如果一次性加载全部书源用于筛选，会增加网络传输、内存占用和 DOM 渲染压力。

本提案只优化“发起搜书时选择搜索范围”的体验，重点解决大规模书源下的定位与组合选择问题。

## 2. 目标与非目标（Goals & Non-Goals）

### Goals

- 在书库搜索页新增可搜索的“自定义搜索范围”选择器；
- 支持同时选择多个书源分组；
- 支持同时选择多个单独书源；
- 支持“多个分组 + 多个单独书源”混合选择；
- 书源候选通过服务端按关键词和分组查询，不设置固定的候选条数上限；
- 选择结果显示清晰摘要，例如“2 个分组 + 3 个书源”；
- 搜索请求按选中范围的并集执行，重复书源自动去重；
- 保留“全部书源”快捷入口，并保持默认搜索行为不变；
- 保留“未分组”作为可选择的特殊范围；
- 选中明确范围后，不再套用当前“全部书源最多 20 个源”的保护上限。

### Non-Goals

- 本次不重做书源管理页的完整列表、编辑器和分组管理流程；
- 本次不引入书源虚拟滚动、无限滚动或新的前端列表框架；
- 本次不改变书源数据模型，不建立新的分组表或多对多关系；
- 本次不改变健康体检、订阅同步、备份导入的业务语义；
- 本次不提供跨用户保存搜索范围的服务端配置；
- 本次不改变“分组内只有已启用书源参与搜索”的规则。

## 3. 核心用户故事（User Stories）

- **Story 1（快速定位书源）**：作为用户，我打开书库搜索范围选择器，输入书源名称、URL 或分组关键词，系统返回全部匹配结果；我可以快速找到目标书源，而不需要在 10,000 条下拉选项中滚动。

- **Story 2（多选分组）**：作为用户，我同时勾选“大灰狼聚合”和“出版”两个分组，确认后发起搜索；两个分组中所有已启用书源都参与搜索。

- **Story 3（混合选择）**：作为用户，我选择“出版”分组，并额外勾选两个不属于该分组的单独书源；系统按这两类范围的并集搜索，而不是错误地取交集。

- **Story 4（去重与范围提示）**：作为用户，我选择某个分组后又单独勾选组内书源；界面显示去重后的范围摘要，服务端不会重复执行同一个书源。

- **Story 5（清空回到全量）**：作为用户，我点击“全部书源”或“清空选择”，所有自定义范围被清除，搜索恢复当前既有的全量书源行为。

- **Story 6（未分组）**：作为用户，我可以勾选“未分组”，它只匹配没有有效分组的书源，不会退化成全部书源。

- **Story 7（大规模稳定性）**：作为用户，即使服务端有 10,000 个书源，我也可以先按名称、地址或分组查询，再完整查看该查询返回的全部候选，不会在无关书源中盲目滚动。

## 4. 方案与交互设计

### 4.1 书库页搜索范围入口

- 保留现有“全部书源”和常用单分组选项卡，作为快速入口；
- 将当前单个书源下拉框替换为“自定义范围”按钮；
- 按钮显示当前摘要：
  - 未选择：`选择书源`；
  - 仅分组：`已选 2 个分组`；
  - 仅书源：`已选 3 个书源`；
  - 混合：`2 个分组 + 3 个书源`；
- 点击按钮打开选择器弹窗；
- 点击“全部书源”时清空所有分组与书源选择。

### 4.2 选择器弹窗

弹窗包含两个相互独立的选择区域：

1. **分组选择**：多选真实分组，并提供“未分组”选项；每项显示已启用书源数量；
2. **书源选择**：输入名称、URL 或分组关键字，服务端返回当前匹配候选；候选以复选框展示，支持跨查询保留已选项；

底部显示：

- 已选分组数量；
- 已选单独书源数量；
- 去重后的预计搜索范围摘要；
- “清空”“取消”“应用范围”按钮。

选择器不因固定条数上限截断查询结果，完整加载当前查询返回的候选结果。

## 5. 技术方案

### 5.1 搜索范围协议

将搜索请求的范围字段调整为：

```kotlin
@Serializable
data class SearchRequest(
    val keyword: String = "",
    val query: String = "",
    val sourceIds: List<String> = emptyList(),
    val groups: List<String> = emptyList(),
)
```

范围语义：

- `sourceIds` 内部按 OR 处理；
- `groups` 内部按 OR 处理；
- `sourceIds` 与 `groups` 之间按 OR 处理；
- 同一书源同时被分组和单独书源命中时只执行一次；
- 两个列表均为空表示未指定范围，保持当前“全部已启用书源”的行为；
- `__ungrouped__` 继续表示 `source_group is null or trim(source_group) = ''`；
- 明确指定任意分组或书源后，不使用“全部书源最多 20 个源”的封顶。

### 5.2 服务端书源候选查询

新增面向选择器的轻量查询接口：

```text
GET /api/sources/picker?q=&group=
```

响应：

```json
{
  "items": [],
  "total": 0
}
```

约束：

- 只返回已启用书源；
- `q` 匹配书源名称、URL 和分组名；
- `group` 可重复传递，用于限定多个分组；
- 不设置固定的候选条数上限，查询结果完整返回；
- 查询使用参数化 SQL；
- 不改变现有 `/api/sources` 管理接口的响应契约。

### 5.3 前端状态

搜索状态由单值改为集合：

```ts
selectedGroups: string[]
selectedSourceIds: string[]
```

`SearchScopePickerModal` 只保存选择状态与候选摘要，不缓存全部书源。应用后由 `searchStore` 发送集合字段。

### 5.4 搜索执行

- HTTP 搜索与 WebSocket 流式搜索共用同一范围解析逻辑；
- 服务端先根据分组和书源 ID 构造去重后的启用书源集合；
- WebSocket `start.totalSources` 返回去重后的实际数量；
- 搜索状态显示当前范围摘要，避免用户误以为仍在搜索全部书源。

## 6. 异常与边界处理

- 书源候选查询失败：弹窗保留已选状态，显示错误和“重试”，不清空用户选择；
- 搜索关键词为空：不发起书源候选请求，提示用户输入至少一个字符；
- 选择的分组没有启用书源：允许应用，但搜索开始前显示 0 个可用书源；
- 已选书源后来被删除或停用：服务端重新校验，自动排除不可搜索项，并在结果中返回实际数量；
- 分组改名后：前端刷新分组摘要，已选范围按新分组名更新；
- 选择器关闭或取消：不提交临时选择，恢复打开前的已应用范围；
- 用户快速连续输入：前端取消上一轮候选请求，只采用最后一次查询结果。

## 7. 验收基准（Acceptance Criteria）

- [x] 书库页可以打开“自定义范围”选择器，并同时勾选多个分组与多个书源。
- [x] 书源候选按名称、URL、分组名服务端搜索，不因固定条数上限截断结果。
- [x] 输入关键词后能快速定位目标书源，并完整加载该查询返回的候选结果。
- [x] 多个分组与多个书源按并集搜索，重复书源只执行一次。
- [x] 未分组范围只匹配 `null` 或空白分组书源。
- [x] 清空或点击“全部书源”后恢复默认搜索行为。
- [x] HTTP 搜索和 WebSocket 搜索的实际书源范围一致。
- [x] 搜索进度中的 `totalSources` 与去重后的实际范围一致。
- [x] 候选查询失败时可重试，且不会丢失已选范围。
- [x] 补充服务端范围解析、候选查询和前端选择器测试。
- [x] 执行前端检查、前端全套测试和相关服务端测试；完整服务端测试另有既有外部实时源失败，详见 [`ACCEPT-035`](../acceptance/ACCEPT-035-large-source-search-scope-picker.md)。
