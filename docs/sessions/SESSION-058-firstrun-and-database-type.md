# SESSION-058 首启只生成配置 + 数据库类型配置项

- 日期：2026-11-14
- 分支：`feat/config-firstrun-dbtype`（叠在 SESSION-057 的配置功能上，同一个 PR）
- 关联：`ServerConfig.kt`、`ConfigFile.kt`、`Application.kt`

## 用户原话

> 「启动时如果有环境变量就按环境变量来，首次启动仅创建配置文件，第二次启动再正式启动，
> 并且添加mysql和postaresql的支持，默认是sqlite，配置文件配置数据库类型什么的」

## 一、首次启动只生成配置（已实现并实测）

以前：文件不存在 → 生成模板 → **同一次启动继续用默认值跑起来**。
现在：`ServerConfig.load()` 返回 `LoadResult`：

| 结果 | 含义 | main() 行为 |
| --- | --- | --- |
| `FirstRun(file)` | 本次刚生成配置 | 打印「请按注释修改后**再次启动**；本次不启动服务」→ **退出**（exit 0，不监听端口） |
| `Ready(config)` | 配置已存在（或写坏时回落） | 正常启动 |

理由：用户要先改数据库/端口/密码，再让服务连正确的库；先拿默认值跑一遍既没意义、还会提前把库建出来。

实测（8231 端口、临时目录）：
1. 第一次 `java -jar` → 输出“已生成配置文件…本次不启动服务”，`config/config.yaml` 存在，**8231 无监听**；
2. 第二次启动 → `healthz=200`，用 `ADMIN_PASSWORD` 登录成功；
3. 把 `database.type` 改成 `mysql` 再启动 → 明确报错并退出（见下）。

「有环境变量就按环境变量来」：优先级仍是 **环境变量 > config.yaml > 默认值**，
且首次生成的模板写入的是「环境变量算出来的实际值」（`effectiveValues()`），不会出现两份不一致。

## 二、数据库类型配置项（sqlite 可用；mysql/postgres 暂未接线）

配置结构（`config/config.yaml`）：

```yaml
database:
  type: sqlite                # sqlite / mysql / postgres（等价 LEGADO_DB_TYPE）
  sqlite:
    file:                     # 留空 = <data.dir>/legado.sqlite（等价 LEGADO_DATABASE）
  mysql:
    host: 127.0.0.1
    port: 3306
    database: legado
    user: root
    password: ""
  postgres:
    host: 127.0.0.1
    port: 5432
    database: legado
    user: postgres
    password: ""
```

- 新增 `ServerConfig.databaseType / databaseJdbcUrl / databaseUser / databasePassword` 与 `isExternalDatabase`；
- 连接串：`mysql` → `jdbc:mysql://host:port/db?...`；`postgres`/`postgresql` → `jdbc:postgresql://host:port/db`；
  可用 `LEGADO_DB_URL` / `LEGADO_DB_USER` / `LEGADO_DB_PASSWORD` 覆盖；
- 启动时若类型不是 sqlite：**打印目标连接串、账号与原因后退出**（不静默跑错库），
  因为数据层仍是 SQLite 方言。

### 为什么这次没有直接跑通 MySQL/PostgreSQL

数据层 `Database.kt` 是 4747 行、全部原生 JDBC + SQLite 方言，实测统计：
`on conflict ... do update` **49 处**、`collate nocase` **38 处**、`pragma` **8 处**、
`autoincrement` 3 处、WAL 4 处。移植要点：

| SQLite | MySQL | PostgreSQL |
| --- | --- | --- |
| `on conflict(c) do update set x=excluded.x` | `on duplicate key update x=values(x)` | 同 SQLite（`excluded` 可用） |
| `... collate nocase` | `collate utf8mb4_general_ci` | 需 `lower()` 改写或 `citext` |
| `pragma table_info/journal_mode` | `information_schema` / 无 WAL | `information_schema` / 无 WAL |
| `integer primary key autoincrement` | `auto_increment` | `generated by default as identity` |
| `create index if not exists` | MySQL 8 **不支持**（要 try/catch） | 支持 |

**结论**：这是数据层级别的重构，必须连真实 MySQL/PostgreSQL 才能验证（本项目规矩是“真跑证据”，不接受只写代码）。
所以本次先把「配置项 + 驱动依赖 + 连接串 + 首启拦截」做完并实测，SQL 方言移植作为下一步；
需要一台能连的 MySQL 与 PostgreSQL（用户内网 Ubuntu 起个容器即可）。

## 验证

- 真跑三连：首启不监听 → 二次启动 200 且能登录 → mysql 类型明确拒绝并退出（见上）。
