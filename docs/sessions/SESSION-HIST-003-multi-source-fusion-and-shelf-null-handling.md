# 历史推演归档：跨书源封面与正文融合、书架空值判定与搜索中断修复

## 1. 历史问题现象与排查背景
- **问题现象 1**：用户编辑书架书籍信息（如自定义封面、标题或作者）时，服务端频繁返回 404 报错 `书籍不在书架中`，即使书籍明确在书架列表中。
- **问题现象 2**：在前端搜索界面中，用户点击“停止搜索”按钮时，搜索没有停止，反而清空结果重新触发了新的全量搜索。

## 2. 曾尝试的无效路径与失败原因
1. **针对问题 1 的无效假设：怀疑前端传入的 `bookUrl` / `sourceId` 主键不匹配**
   - *排查发现*：前端发送的主键完全合法。根因在于 SQLite 查询 `cover_key` 字段时，若该书初始没有封面，查询结果为 `NULL`。在 Kotlin 服务端使用 Elvis 运算符 `val cover = rs.getString("cover_key") ?: return null`，直接导致整行记录被判定为“不存在”，进而抛出 404。
2. **针对问题 2 的无效尝试：仅在点击事件中调用 `searchStore.abort()`**
   - *失败原因*：停止按钮被包裹在 `<form>` 标签内，且没有显式声明 `type="button"`。在 HTML 规范中，表单内的 `<button>` 默认 `type="submit"`，点击时会触发表单 `onSubmit` 默认事件，从而重新发起了新的搜索请求。

## 3. 最终落地的解决策略
1. **解耦行存在性检查与可空字段提取**：
   - 修复 `Database.kt` 中的空值处理逻辑，显式通过 `COUNT(*)` 或主键存在性校验，不能用可空字段（如 `cover_key`）的非空判定代替行存在性。
2. **表单按钮类型显式约束与 AbortController**：
   - 在前端所有非提交按钮上强制标注 `type="button"`。
   - 正确绑定 `AbortController` 并在停止时分发终止信号，阻断未完成的书源检索流。

## 4. 沉淀至部落知识库的经验条目
- **[Kotlin/SQL] 严禁使用可空列做存在性 Elvis 判断**：在 JDBC / SQLite 结果集提取中，务必区分“字段值为 NULL”与“数据行不存在”。
- **[前端/Form] 按钮显式声明 `type="button"`**：表单内的所有辅助操作按钮（如停止、重置、筛选切换）必须显式标记 `type="button"`，防止误触表单提交。
